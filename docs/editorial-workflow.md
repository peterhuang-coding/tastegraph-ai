# TAPE 素材、策展与发布反馈

2026-09-13 本地更新。运营入口：`http://127.0.0.1:8787/editorial.html`；发布登记：`http://127.0.0.1:8766/publish-log`。

## 每次怎么做

1. 查看素材原图和来源上下文；记录画面用途、使用场景、适合讲什么、取舍理由。未知年份留空，核验后附证据。
2. 从素材中选 1–18 张建立候选图集。写明整组命题、逐图角色、画面证据、入选理由和顺序。
3. 审核通过后导出原图与文案起稿。检查并编辑标题、正文与图片顺序，再通过账号实际发布流程提交。
4. 把提交状态、真实发布时间、实际观测时间和互动计数分别登记。缺失数据留空；审核中不等于已发布。

系统每天 03:00 继续采集，08:00 / 20:00 生成至多 6 组研究候选（每组至多 9 张，由可用内容决定）。候选不会自动通过策展审核。已有定时发布与自动账号反馈任务仍保持关闭。

## 数据与推荐规则

- `image_provenance`：发现页、实际抓取页、规范链接、页面类型、页面标题/作者、逐图 alt/图注/作者/上下文和采集时间。没有图片日期证据时保留未知。
- `image_editorial`：画面、场景、选题、运营决定、理由、出处核验，以及照片创作/物件原设计/项目发布/网页发表四组独立年代证据。
- `pack_editorial`：整组命题、顺序和逐图判断；`editorial_events` 保留行动者和审阅记录。助手样例与运营输入有独立标记。
- `publication_pack_links`：文件夹与数据库图集的稳定身份；`publication_observations`：幂等、带观测时刻的实际状态和计数。已有发布时间不由提交时间代填。

图谱评分读取 `north_star → concept/source` 的偏好边；修改已有偏好权重会改变候选得分。来源具体 URL 优先于冲突的历史 ID。未能确定来源时保持未知，不凭同域的任意栏目归属。

候选评分是可解释规则：`0.5 × 归一化图谱分 + 0.2 × 已核验出处 + 0.1 × 具体页面 + 0.1 × 优先研究 + 0.1 × 明确喜欢`。这是初始规则，没有声称通过发布数据训练最优权重。文件与 API 入口共用规则；按显式选题或同一具体页面组织研究候选，轮换来源。首页/栏目图片不按同页拼成论点。

网站图标被过滤；按 ID、URL、内容 SHA256 去重，包括其他 ID 下已提交的同图。抓取与导出保留原始字节，不统一裁切或做旧。底库中的历史错误不会凭猜测批量改写。

## Feedback 的范围

素材标签影响候选检索和上下文分；单图“喜欢/不喜欢”才属于审美偏好。通过/退回一组图只记录这组的编辑决定，不把每张图隐式记为喜欢/讨厌。平台互动作为独立结果证据，不直接加减审美权重。

一篇笔记无法证明某种审美、来源或顺序有效。先积累多个可比较的图集及真实曝光/互动观测，再评估改动。未采集、未到时间的 24h/48h 数据是空值；审核中显示的零不用于学习。

## 启动与验证

在仓库根目录启动 API：

```sh
python -m taste_graph_ai.server
```

工作台可另开终端启动（端口按本机情况选择）：

```sh
QUEUE_PORT=8766 python scripts/queue_server.py
```

API 默认端口8787。检查 `/api/health`，然后打开 `/editorial.html`。如果工作台使用其他端口，设置 `TASTEGRAPH_WORKBENCH_URL`；如果 API 不在8787，工作台需设置 `TASTEGRAPH_UPSTREAM_API`。

多 checkout 部署时，为服务显式配置同一 `TASTEGRAPH_BASE_DIR` 与 `TASTEGRAPH_DATA_DIR`。数据库、图谱、图片和发布目录应指向同一套权威数据；仅共享数据库不足以保证一致。生产服务关闭 `TASTEGRAPH_RELOAD`，按实际进程身份更新，保留原有未提交工作。

运行本次回归：

```sh
python -m pytest tests -q
node --check taste_graph_ai/static/js/editorial.js
```

用临时数据库验证图谱改权重、来源冲突、原图指纹去重、审核门槛和范围、导出顺序、旧入口门禁、发布计数空值与幂等导入。历史 `image_post_log` 的兼容测试直接建立表数据，无需安装可选的旧界面分支。

## 历史记录迁移与恢复

`migrate_editorial_workflow.py` 是有界历史记录迁移器，要求显式输入 DB、内容根目录、标注样例、原始发布观测及登记文件。默认复制 DB 并演练两次；`--apply` 才写入明确指定的数据库。它验证原始图序、来源证据、已有用户批准与真实观测，保留已存在的人工标签，不调用平台。当前迁移器针对已有 Rams 记录格式；用于其他历史记录前应先核对格式及约束。

部署前通过 SQLite 在线备份 API 保存数据库，并备份将替换的代码。新表为增量创建；回滚优先恢复对应代码。恢复整库前确认备份后没有新编辑或发布观测，避免丢失后续工作。本机路径、账号登记、真实指标和恢复清单应保存在私有项目记录中，不能提交到源码仓库。
