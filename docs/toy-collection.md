# 玩具收藏使用指南

## 用户指南

本工具用于整理**你真实拥有或亲眼核验过的单个玩具**，最多添加 18 张 JPG、PNG 或 WEBP 照片；单张不超过 10 MiB、20 MP。原始照片默认私有，并生成不含元数据的预览。归档内相同字节的照片会被识别为重复；只有你明确设为公开的照片会进入导出文件。

使用步骤：

1. 在运行此任务分支的本地预览服务中打开 `/collections.html`，新建或选择一个玩具。当前交付为待验收分支，尚未合并或部署到日常服务。
2. 上传照片，建议拍摄正面、背面、底部、铭文、包装、瑕疵等证据角度。
3. 填写你已知的故事和私有备注；私有备注不会公开导出。
4. 按事实逐条编辑来源与结论：来源可为本人观察、用户说明或外部资料；确定性分为已有证据支持、有依据的推测、尚未确认；复核状态另分待复核、已接受、有争议。外部证据需填写 URL、标题、摘录或准确释义、实际访问时间和适用范围。年份需区分设计年、首发年和具体实物年，不能混填。
5. 手动添加背景资料。系统不会自动验证资料真伪。
6. 生成草稿：它会把已接受的公开说法和证据确定地编排为“证据汇编”，可附真实用户故事；三个标签提供写作切口，尚未生成三篇 AI 故事。你可以编辑标题、正文和排列顺序。
7. 确认后导出不可变 ZIP：包含所选公开照片、去除元数据的编号图片、标题/正文和选中证据。此功能不会调用发布流程。

注意：确认草稿后，如事实或证据变化，已确认内容不会自动改，只能保留原文并重新处理。研究、OCR、维基查询都必须由你主动开始；OCR 仅在本地对 1–4 张已选图片运行。系统不能视觉识别、分类或鉴定玩具，也不会自动深度研究、自动回答或导入结论。维基查询只发送已确认名称到中英文维基官方 MediaWiki API，问题和缺失分析留在本地。最多同时运行 2 个任务，单次预算 90 秒、3 个页面、6 次请求，不自动重试或跟随跳转；取消会停止新操作，已开始任务最多等待约 20 秒。资料范围可能不足，仍需品牌方或博物馆等一手来源。验收必须以真实玩具和照片为准，测试数据不能替代。

## 开发者指南

服务仅提供本地 HTTP API，允许 loopback/本机地址访问并校验同源；不要暴露到公网，也没有认证、多用户或公共托管能力。系统按单进程、单 worker 运行，不支持多 worker。复用现有配置中的 `DATA_DIR`、`DB_FILE`；测试与预览路径必须隔离，测试使用临时数据。

照片、权限、声明、来源和导出状态均应由本地数据模型持久化。重启会将中断的任务记为失败，保留已保存的成果，需要本人重新启动；但程序关闭期间不会执行任何任务，重启后也不会替你继续未安排的研究。不要增加定时任务、自动抓取、多模态识别或真伪认证功能。外部来源必须保留访问范围、URL、标题和摘录；无法实际访问时不得包装成已验证证据。

公开导出只能选择用户明确公开的照片，生成前去除元数据，并固定编号、正文、顺序和证据清单，确保同一 ZIP 不可被静默改写。

## 本轮验证（2026-09-27）

- 127 项相关测试通过：藏品数据与 API、研究取消/恢复、原有策展和发布记录回归。
- 浏览器使用明确标注的合成玩具，完成多图上传、单图失败与重试入口、证据复核、手改正文、图序调整、确认导出和刷新恢复。桌面及 390px 移动视口未出现横向溢出。
- 实际执行本地 Tesseract OCR 和公开维基背景查询；来源保存访问时间，未自动升级为物件事实。
- 导出包逐项核对正文、图序、所选证据和未知标记，排除私有备注、私有照片、原始文件名和图片元数据。修改证据后旧导出包保持原 SHA，已编辑正文保留且需重新确认。
- 真实玩具照片尚未提供；准确身份、版本和省时效果均未验收。

复现相关测试：

```sh
python -m pytest tests/test_collections.py tests/test_collection_research.py tests/test_collections_api.py tests/test_editorial_workflow.py tests/test_publication_records.py -q --tb=line -p no:cacheprovider
node --check taste_graph_ai/static/js/collections.js
```

本地 OCR 为可选依赖，需已安装 `tesseract`；缺失时能力入口明确不可用。公开背景查询使用现有 `httpx`。测试和预览应使用隔离数据库，不以生产藏品数据作测试夹具。
