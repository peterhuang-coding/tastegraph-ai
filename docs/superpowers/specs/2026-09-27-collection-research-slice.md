# Collection research slice: explicit, bounded, evidence first

This extends the stored collection workflow with usable local OCR and limited public-background lookup. It does not claim automatic toy authentication, comprehensive brand-archive research or measured time savings. No scheduled work, paid providers, model calls, credentials, crawlers or publication actions.

## Local identification clues
Use installed Tesseract (optional executable discovered with shutil.which, never install automatically). The owner explicitly chooses 1–4 photo IDs when starting identify. Read only the store-provided stripped preview paths for those IDs; no user-supplied path, no shell. Explain that processing remains local, selected private photos remain private, recognized text may be wrong. A subprocess timeout of 20 seconds per photo, total job deadline90 seconds; check cancellation between images and before accepting any result. Use eng+chi_sim when available, eng fallback only if supported. Bound stdout/text length, record per-photo stage errors without pretending completion. Empty OCR is a valid result with a concrete bottom-marking/packaging reshoot question. Return observations with photo_id and recognized text, optional finite manufacturer-name candidates when their name literally appears, each marked tentative and never a model/version or authenticity conclusion. Do not mutate target, claims or draft. Missing executable is a real capability block before starting.

## Public background lookup
An explicit research click sends ONLY the confirmed target label and 1–3 owner-reviewed question strings, plus language en or zh, to the public MediaWiki API. Require allow_external=true. Never send photos, photo captions, known_info, personal_story, private_notes or existing draft. Up to3 unique pages and6 HTTP requests, each <=10 seconds, total<=90 seconds; no automatic retries, redirects or bypass on403/429. Use a descriptive User-Agent. All hosts are hardcoded en.wikipedia.org/zh.wikipedia.org; no arbitrary URL fetch or secrets. Search via action=query,list=search, then read actual page text via prop=extracts,explaintext=1,exchars=10000; do not treat search snippets as source text. A returned source has title, canonical page link, accessed_at, a short excerpt from the retrieved text, scope=background only, limitations=not evidence for this specimen version/production/authenticity. Unknown publication/photography/object years remain null. Deduplicate pages; zero results or empty readable text yields awaiting_review with explicit gaps. A transport/access failure yields failed with source/stage/error evidence and any already-read sources. Never label background hits as answers to the questions; record unanswered question gaps. Surface this as “公开百科背景检索”, with brand catalog/museum evidence still needing manual additions in the existing claim editor.
Official protocol references: https://www.mediawiki.org/wiki/API:Search and https://www.mediawiki.org/wiki/Extension:TextExtracts .

## Runtime contract
One worker per object; small in-process ThreadPoolExecutor(max_workers=2), explicit initiation only. Persist run identity before dispatch; on restart, running runs from the previous runtime become failed/interrupted. Store begin/finish methods and cancellation reject late/superseded results. Runtime must not overwrite edits made after start. Store the actual target/question/selected-photo snapshot in each result so it remains explicitly scoped if the owner edits the live fields while work runs; do not silently rebind old results to new inputs. Protect duplicate requests and dispatch failures; check expected_revision before initiation within the same lock/transaction as changing state (no check-then-act race). Cancellation signals work and persists immediately; no new work starts after the signal; in-flight HTTP/OCR may finish but cannot be applied. No fake progress percentages. Stage updates should be conditional on matching active run ID.
Capability GET endpoint /api/v1/collections/capabilities (register before /{id}): {identify:{available,reason},research:{available:true,scope:"公开百科背景检索",max_questions:3,max_pages:3},budget:{seconds:90,max_photos:4}}.
start_research action accepts {mode,photo_ids? (identify),allow_external? (research),language?:"en"|"zh"} and returns running document. UI polls only while running; preserves unsaved fields/draft, displays actual result observations/sources/gaps/errors safely, and stops polling terminal. Make limitations visible before starting and in result.

## Validation
Temporary DB, fake subprocess and httpx transport tests must cover payload data minimization, explicit consent, no duplicate dispatch, cancelled late response, restart interruption, access-limit stop, empty evidence success, no search snippet evidence, stage/source error preservation, no auto-claim/publication/draft edits. A real local OCR run can use clearly synthetic text; a live public request (if reachable) verifies connectivity only, never actual toy identity. No real owner photos supplied yet.
