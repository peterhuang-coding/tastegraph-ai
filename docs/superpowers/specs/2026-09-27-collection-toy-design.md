# Toy collection v1 design and interface contract

User-approved scope: single owner, one physical toy with many real photos, known facts, questions, optional personal story, private notes; evidence-led research then an editable post. This is a new feature in an existing FastAPI + vanilla JS app. Do not change crawlers, graphs, publication automation, or production data. Only synthetic inputs in tests. No real user's photos have been supplied.

## Model and invariants
Use a separate SQLite collections table in the configured DB, storing a versioned JSON document per object; assets live under a private collection directory, never the global images/exports mounts. Implement transactions/CAS to protect concurrent edits and idempotent creation. Inject db_path/assets_dir into CollectionStore so tests cannot touch production. All times ISO timezone-aware. All persisted IDs server-generated opaque IDs except create_token idempotency key.
Document shape (detail responses use this unwrapped object):
{id,title,category:"toy",known_info,questions:[],personal_story,private_notes,target:{label,confirmed:false},revision:int,created_at,updated_at,photos:[],claims:[],research:{id:null,state:"needs_info",phase:"",error:null,result:null},draft:{title:"",body:"",image_ids:[],claim_ids:[],confirmed:false,needs_review:false,version:0},exports:[]}
Photos: {id,name,role,caption,private:true,allow_model:false,sha256,url}. Images default private and no model permission; owner may explicitly mark public, separate model permission. Accept JPG/PNG/WEBP decoded by Pillow, <=10MiB original, <=20 megapixels, 1..18 per object; reject malformed/unsupported decoded data early (decoded format is authoritative, not the filename suffix). Reencode preview to JPEG/PNG without EXIF/GPS; preserve private original. Same-byte repeat in SAME object returns existing photo; across objects do not merge. Do not trust supplied filename as filesystem path. UI reports per-file outcome. Photo ordering/removal cannot mix another object's IDs.
Claims: {id,field,text,origin:"observation"|"user"|"external",certainty:"supported"|"inferred"|"unknown",review:"pending"|"accepted"|"disputed",public:false,version:int,evidence:[{title,url,excerpt,accessed_at,scope,limitations}]}. External supported requires nonempty evidence with title/http(s)URL/excerpt/time/scope. URLs are recorded only, NOT fetched by this store. Acceptance never changes certainty or origin. User edits to an external fact must not silently keep external supported status when text changes: force review pending and certainty unknown unless renewed evidence is explicitly supplied and validated. Design date/first release/instance production are separate fields by convention/UI choices. No arbitrary confidence score.
Changes to claims in draft.claim_ids mark draft.needs_review=true and confirmed=false, preserving title/body exactly. Photo privacy/removal changes affecting draft invalidate draft confirmation. Exports already made are immutable snapshots; later corrections flag live draft only. Draft manual edits never overwritten by research/identification responses. Text length limits enforced. Private_notes never appear in model input/public output. User must explicitly choose public personal-story inclusion; not default.
Research state enum needs_info,ready,running,awaiting_review,failed,cancelled. Target confirmed + >=1 readable photo + 1..3 questions yields ready; confirmation does not start work. No parallel research per object; start only explicit. Starting creates unique run id; cancel terminal for that run; late results cannot replace cancelled/superseded run. Stored interrupted runs can be marked failed with clear recoverable reason by runtime on restart, not falsely complete. No evidence is a valid awaiting_review result with gaps. Version is checked for user mutations; external worker completion must NOT overwrite user fields.

## Store and API (frozen wave1 interface)
Python module taste_graph_ai/services/collections.py exports CollectionError(message,status_code=400), CollectionStore(db_path,assets_dir), methods list_items(), create(payload), get(item_id), update(item_id,payload), add_photo(item_id,payload), action(item_id,payload), photo_path(item_id,photo_id), export_zip(item_id,export_id). store methods return JSON dicts except paths/zip. Every mutation after create carries expected_revision integer; stale =>409. create uses create_token stable token; reused token same initial payload idempotent, different initial payload409.
Route factory create_router(db_path,assets_dir) in taste_graph_ai/api/routes/collections.py. No import-time production DB creation. router export lazy routes use config.DATA_DIR / collections-media and config.DB_FILE.
GET /api/v1/collections => {items:[{id,title,category,updated_at,revision,photo_count,research_state}]}
POST /api/v1/collections JSON {create_token,title,known_info,questions,personal_story,private_notes} => document
GET /api/v1/collections/{id} => document
POST /api/v1/collections/{id} JSON {expected_revision, title?,known_info?,questions?,personal_story?,private_notes?} => document
POST /api/v1/collections/{id}/photos JSON {expected_revision,name,data_base64,role?,caption?,private?,allow_model?} => document (duplicate photo returns document unchanged)
GET /api/v1/collections/{id}/photos/{photo_id} => metadata-stripped preview bytes, correct media type
POST /api/v1/collections/{id}/actions JSON {expected_revision,action,...} => document, except export returns {export_id,title,body,image_ids,download_url}
Actions:
- reorder_photos: {photo_ids:[ALL photo ids exactly once]}
- update_photo: {photo_id,private?,allow_model?,caption?,role?}
- remove_photo: {photo_id}
- confirm_target: {label,confirmed:true|false}
- save_claim: {claim:{id? plus fields above}} => upsert validated claim, incremental claim version
- generate_draft: {include_story:false,angle:"观察细节"} => assemble ONLY accepted public claims and optionally user-supplied story; never invent. If draft.body already exists,409 (explicitly edit existing draft). Clearly label as evidence-based assembly rather than pretending AI generation. No forced 3 angles. Unknown/inferred labels kept in draft if included; disputed/pending excluded.
- save_draft: {title,body,image_ids,claim_ids,confirmed:false|true}. References must belong to object; image_ids only public photos; confirmation requires at least 1 public image, nonempty body/title, privacy_checked:true; snapshot dependencies to protect re-confirmation.
- start_research: {mode:"research"|"identify",allow_external:false|true}. Wave1 safely return409 "研究执行器尚未配置" rather than fake run; execution integration will extend in wave2. Keep store begin_research(item_id,mode), finish_research(item_id,run_id,result,error=None),cancel via action; tests exercise these lifecycle methods. No network/model call wave1.
- cancel_research: {} => cancelled current running run; preserve prior work.
- export: {privacy_checked:true} => immutable snapshot ZIP with title.txt,body.txt, ordered metadata-free public image copies, evidence.json using ONLY referenced public accepted claims. Require draft.confirmed and !needs_review, current references valid and public. Never include private_notes, known_info, original filenames, private photos or full archive JSON. Recorded JSON includes export_id/date/content hash and cloned safe fields only.
GET /api/v1/collections/{id}/exports/{export_id} => ZIP, bounded controlled path, no arbitrary filesystem paths. Subsequent edits cannot modify snapshot.
Errors HTTP {detail:"helpful Chinese reason"}; missing404, stale409, invalid400 or too large413. Bound collections state payloads; content text rendered by UI using textContent or escaped HTML, never untrusted innerHTML.

New /collections.html and /js/collections.js /css/collections.css. Link from existing index header/navigation (main agent integrates). Single workspace: left list/new item; right photo contact sheet (cover not cropped), name/known info/questions/private details, confirmed research target, evidence cards with three truth levels and separate user review, draft editor/order/export. Default category玩具. Use white warm paper #f6f4ef, ink #292b2a, muted #74766e, moss #52644d, rule #dedfd6, warning #99613b. Serif restrained title (Georgia/system serif), system Chinese body, monospace archive record id. Archive ledger top line/numbered photo contact sheet as signature, no gradients/cards everywhere. Explicit loading/error/empty states, responsive and keyboard labels. No made-up demos on empty screen. Warn unsaved draft edits and preserve textarea content during polling; server errors keep entered values. Per-file upload status and retry without new object. New object create token persists until success to prevent duplicate rapid click; don't fake-success actions. Research identify buttons say capability not configured when409. Mode selection and external permission separate/private checkbox defaulttrue. Show no fake percentage. Plain Chinese user-facing labels, no implementation jargon. Export requires explicit privacy checklist/confirmation. Closed tab returns persisted object. Do NOT automatically publish or register a publication.

## First slice acceptance
Behavior tests using temporary DB/assets: create idempotency+conflict; partial photo errors; same-object dup/cross-object isolation; payload/decoded dimensions/path validation; claim scope/evidence requirements; acceptance doesn't upgrade uncertainty; corrected evidence flags draft without body overwrite; stale update409; cancelled run rejects late completion; no evidence valid result; private media excluded; immutable export; export image EXIF removal; no model/network on startup.
JS syntax and real browser E2E against isolated API. Generated source-string tests were rejected because they mirrored implementation and misclassified equivalent DOM behavior. Real AI identity, external web research and owner's time savings remain unverified until configured + real sample supplied, not silently treated as completed.

## Implemented integration scope
The first-wave unavailable-executor placeholder above is superseded at the HTTP action route by the bounded research adapter described in `2026-09-27-collection-research-slice.md`. The store itself performs no networking. Runtime OCR only reads explicitly selected local previews; research sends only the confirmed target label to fixed MediaWiki hosts. Questions remain local gaps, with no automated answers or claim insertion. Interrupted runs become failed; cancellation keeps completed checkpoints and blocks late writes. Endpoint access requires a loopback peer, localhost host and same-origin requests. Single process/worker only. Public export uses the owner-confirmed references; unknown facts remain labeled. Reconfirming after a correction requires the current archive revision and explicit privacy acknowledgment; it does not automatically rewrite prose.
